# Watch7: вибір «Пішки» після пошуку маршруту

Зміни коду без APK і без зміни версії, package, підпису чи даних.

## Підтверджено з коду та фото

- На фото користувача вже відкрито три картки: автомобіль, громадський транспорт,
  пішки. Нижня картка частково обрізана круглим екраном.
- Попередній код після вибору місця безумовно чекав окрему кнопку «Маршрут».
  Якщо Карти одразу відкривали вибір транспорту, цей етап не завершувався.
- Пошук «Пішки» вимагав відповідності на початку підпису: опис із часом на
  початку не знаходився.
- Резервний жест використовував фіксовану частку висоти екрана, а не межі
  видимого елемента. Це не доводило вибір потрібної картки.

Точне дерево Accessibility фізичного Watch7 не отримано. Зв'язок цих
дефектів із конкретним випадком користувача потребує перевірки на пристрої.

## Виправлення

| Файл | Зміна |
|---|---|
| `JarvisWatchScreenService.java` | Розпізнає вже відкритий вибір із трьох карток; шукає «Пішки» в складеному описі; спочатку натискає Accessibility-вузол або його батька; жест обмежений видимою частиною вузла. |
| `JarvisWatchUiRules.java` | Розпізнає українські, російські та англійські назви режиму і тривалість; перевіряє розташування трьох великих карток. |
| `JarvisWatchMapsController.java` | Повторює перевірку актуального дерева замість сліпого натискання внизу; після тайм-ауту зберігає передавання пішого режиму через Maps intent. |
| `JarvisWatchUiRulesTest.java` | Перевіряє складені підписи, локалізацію, час/відстань, неповний список, зміщене вікно, дублікати часу та рядок за межами екрана. |

Для карток без назви режиму використовується **евристика за фото користувача**:
збіг назви пункту призначення, рівно три окремі видимі рядки тривалості,
достатні проміжки між ними, третій рядок унизу екрана. Натискання — по
центральній осі годинника на висоті видимої третьої картки. Це не є універсальним
контрактом Google Maps: якщо порядок або склад карток зміниться, алгоритм
потрібно перевірити знову. Інший екран з ідентичною структурою залишається
ризиком; позначений Accessibility режим має пріоритет над евристикою.

Збережені перевірки застосунку на передньому плані, пошуку та клавіатури.
Стан невідомий — очікування, а не натискання за координатою. Повторні спроби
обмежені за часом. Успішний ACTION_CLICK/жест означає тільки прийняте
натискання, а не підтверджений початок навігації.

## Перевірки

Автоматичні контракти запускаються через `voice-tests.yml`, разом із
компіляцією Java Android (`compileDebugJavaWithJavac`). APK цей workflow не
створює. Результат конкретного запуску див. GitHub Actions для коміту.

Фізичні сценарії нижче **потребують перевірки на Watch7** після окремо
замовленої користувачем збірки:

- [ ] «Знайди дорогу до Стебника»: одразу відкриті три картки → нижня «Пішки».
- [ ] Місце з окремою кнопкою «Маршрут» → вибір пішого режиму.
- [ ] Частково обрізана нижня картка → натискання видимої частини.
- [ ] Повільне завантаження → повторні перевірки через 2 секунди.
- [ ] Відкрита клавіатура, головний екран, інша програма → жодного сліпого натискання.
- [ ] Невідоме розташування / немає пішого маршруту → без випадкового вибору транспорту.
- [ ] Повернутися до Дімона та виконати наступну команду; «Де я» працює.
- [ ] Pixel: телефонні Карти та передавання команд без регресії.

Емулятор і фізичні пристрої в цій роботі не використовувалися.
