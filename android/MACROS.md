# Джарвіс — локальні макроси (перший етап)

Дата початку: 2026-11-11. APK поки **не збирати** без окремої команди власника.

## Правило
Кожен макрос: назва + тригер + упорядковані дії + необов'язкові обмеження.
Відсутність обмежень дозволяє запуск щоразу після тригера.
Коли вони є, усі повинні бути істинними (AND); відмова — fail-closed.
Обробка й локальне сховище не залежать від платної ШІ-моделі.

## Реалізовано в коді (ще не перевірено Android-збіркою)
- Окремий екран «Макроси» через навігацію з головного екрана Джарвіса.
- Список, редагування, enable/disable, видалення, ручний тест макросу.
- Голосовий тригер (власна точна фраза без обов'язкової частини «Джарвіс») у MainActivity та FloatingJarvisService.
- Щоденний локальний часовий тригер через AlarmManager, ресклад після перезавантаження.
- Тригери підключення/відключення живлення.
- Послідовні команди керування з наявного DeviceCommands; екранні послідовності — через JarvisSequenceExecutor з перевіркою Accessibility.
- Дії: пауза, сповіщення, вібрація, явно схвалена root-команда через `su -c`.
- Обмеження: часове вікно включно з переходом через північ, дата, день тижня, мінімальний заряд батареї,
  стан зарядки, точний SSID Wi-Fi, геозона (координати й радіус).
- Визначення геозони лише по координатах, що не старші 10 хвилин; якщо геолокації/дозволу немає — НЕ виконувати.
- Голосове скасування: «скасуй макрос» / «зупини макрос». Root процес примусово завершується за можливості.
- Чітке збереження макросів в окремі SharedPreferences, без відправки на сервер.

## Важливі обмеження поточного коду
- Багато функцій MacroDroid ще НЕ реалізовано. Не стверджувати повну сумісність.
- Команда Джарвіса як дія зараз підтримує лише ті фрази, що розбираються локальними
  DeviceCommands або JarvisCommandSequence. Повноцінна інтеграція всіх команд та їхніх параметрів — наступний етап.
- Складні дії з інтерфейсом інших застосунків потребують дозволу Accessibility та відповідного стану екрана.
- Android 12–17 обмежує запуск UI й тривалих процесів з фонового BroadcastReceiver.
  Для надійного фонового виконання послідовностей потрібна окрема foreground/work система.
- Тригер погоди, календаря, геопереходу, сповіщення, SMS, змін Wi-Fi і сенсорів — поки НЕ реалізовано.
- Умови OR/NOT, вкладені IF/ELSE, цикли, змінні, шаблони, динамічні параметри — наступний етап.
- Root сам по собі не надає користувацьких дозволів для мікрофона/локації, не скасовує
  всі обмеження Android і може вимагати підтвердження в Magisk.
- Часовий тригер без дозволу exact alarms може спрацювати приблизно, не до секунди.
- Тривалі root-скрипти чи паузи зі стану broadcast не гарантовано виконуються після завершення короткого вікна процесу.
- Не запускати shell-команди, складені ШІ, без перегляду і явного підтвердження власником.
- Поточний макрос не може одночасно виконуватися разом з іншим: додатковий запуск відхиляється.

## Рекомендований каталог другого етапу (за MacroDroid)
**Тригери:** голосова довільна фраза, кнопка, гарнітура, годинник, час, день,
зарядка, рівень батареї, Wi-Fi/BT/NFC, повідомлення, запуск/закриття застосунку,
екран/розблокування, геозона вхід/вихід, погода, календар, струшування, датчики,
HTTP/webhook, intent, зміни змінної, SMS/виклики за дозволами.

**Дії:** системні налаштування з параметрами, виконання послідовних screen UI дій,
зміна гучності по каналах, вибір застосунків, текст, сповіщення, локальні файли,
таймери, будильники, TTS, медіа, мережевий HTTP з дозволеними доменами,
рутини годинника, фонова робота, root-профілі.

**Обмеження:** вкладені групи AND/OR/NOT; час, дата/свята/дні, геозона,
акумулятор/заряджання, мережі, стан екрана/застосунку, гарнітура, погода,
змінні, режим телефона/годинника.

**Логіка:** IF/ELSE, очікування фактичної готовності UI, таймаути, повтори,
цикли з лімітами, скасування, повторне використання блоків дій,
історія виконання з поясненням пропущених кроків.

## Чекліст перед наступним APK
1. `./gradlew :app:compileDebugJavaWithJavac` (без збірки APK), перевірити компіляцію.
2. Створити голосовий макрос: «Джарвіс, робочий режим» → гучність 30% → пауза → сповіщення.
3. Перевірити без обмежень, з невиконаним обмеженням, з нічним часовим діапазоном.
4. Перевірити геозону з відсутнім дозволом; старі координати повинні блокувати запуск.
5. Перевірити запуск з плаваючого обличчя і стандартного екрана.
6. Перевірити root без дозволу, після дозволу, і скасування.
7. Перевірити тригер о HH:mm, а також після перезавантаження.
8. Перевірити, що наявні діалоги, Spotify, таймер, голос, інструменти екранного керування не зламані.
9. Лише після цих тестів, за окремою командою, збирати підписаний APK із
   **тим самим applicationId/signing key**, але вищим versionCode.
