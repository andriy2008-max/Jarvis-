# Дімон 0.1.41 (versionCode 51) — підписаний тестовий кандидат Watch7 + Pixel

Цей APK є **pre-release / тестовою версією**. Виправлення підтверджені аналізом коду та автоматичними тестами, проте фізичний Galaxy Watch7 SM-L310 і Google Pixel 9 недоступні для виконання зовнішніх команд в CI. Не називати остаточно стабільним до реальних тестів.

## Ідентичність і сумісність
- Application ID: `com.andriy.jarvis.stable`, незмінений.
- `versionName: 0.1.41`, `versionCode: 51` (попередній реліз 0.1.40 / 50).
- Підпис: **оригінальний стабільний GitHub Secrets keystore**, перевірка digest проти `android/RELEASE-CERT-SHA256.txt`. Ніяких нових ключів/сертифікатів.
- Формат локальних налаштувань і збережених даних не мігрувався; функції Finance, Macro, Telegram та інші не видалялися навмисно.
- Установити поверх 0.1.40, **не видаляти** встановлений Дімон, інакше втратяться дані.

## Підтверджені проблеми в попередньому коді та виправлення (це НЕ висновок зі справжнього Watch7 logcat)
1. `JarvisWatchScreenService`: незахищений асинхронний callback Accessibility-gesture міг викинути RuntimeException у UI-потоці; додано перехоплення та приватний діагностичний запис.
2. `JarvisWearPhoneLink`: некоректний ACK Pixel міг залишити pending-запит до тайм-ауту; додано очищення очікування й повідомлення про помилку.
3. `JarvisMicrophoneChoice` + `JarvisHeadsetAudioRouter`: гарнітура Bluetooth могла впливати на маршрут вхідного аудіо Watch7; пріоритет вбудованого мікрофона годинника; не блокувати розпізнавання при відмові Wear OS. Стандартний SpeechRecognizer може ігнорувати побажаний маршрут — лише фізичний тест перевірить результат.
4. `JarvisWatchSpotifyController`, `JarvisWatchScreenService`, `JarvisWatchUiRules`: Spotify Wear OS тепер перевіряє Home, за потреби свайпає вправо, коректно обробляє відкриту клавіатуру, довше свайпає угору, перевіряє фактичне введення назви пісні. Плейлист за назвою переглядається у видимих рядках бібліотеки та прокручується **без глобального Search**, з обмеженнями спроб і пауз.
5. `JarvisWatchMapsController` та `JarvisWatchScreenService`: для «Де я» натискає підтверджену верхню ліву кнопку карти, якщо відкритий домашній екран Карт. Для «Знайди дорогу до…» спочатку шукає «Пішки» за текстом, потім лише після етапу Directions, за відсутності IME, одним жестом натискає **50% ширини / 88% висоти** самого Watch7. Фактичне призначення кнопки на конкретній версії Google Карт потребує тесту.
6. `ScreenControlAccessibilityService`, `SpotifyTrackSearchRules`, `SpotifyPlaybackController`: на Pixel сторінка Spotify Search з великим полем «Що ви хочете послухати?» більше не потребує повторного натискання нижньої вкладки. Для Compose додається підтверджений UI-пошук рядка і резервне натискання у видимому проміжку між Search-заголовком і Music/Podcasts картками; до трьох перевірених повторних спроб, лише на Spotify. Перед введенням назви підтверджується Spotify-owned редактор / IME.
7. `JarvisWatchUiRulesTest`, `SpotifyTrackSearchRulesTest` та інші: автоматичні контракти на межі, повтори, зупинку й небезпечні екрани.

**Важливо:** пункти вище описують ризики попереднього коду та реалізовані захисти, а не підтверджені фізичні першопричини кожного збою.

## Автоматична перевірка релізного коміту
GitHub Actions workflow `watch7-audit.yml`:
1. Java контракти й тести подвоєння callback.
2. Android debug-компіляція, побудова тестового APK для інструментальних тестів.
3. Wear OS emulator: synthetic lifecycle/voice-dispatch tests (НЕ фізичний мікрофон, НЕ реальна Spotify/Maps UI-автоматизація).
4. Відновлення постійного сертифіката, підписаний `assembleRelease`, `apksigner` check, `aapt` check на package/version, SHA-256.
5. Завантаження результатів; **реліз лише з main та після перевірок**; новий реліз не перезаписує v0.1.40.

## Залишкові ризики
- Немає дійсного `logcat` з фізичного Watch7, тому **першопричина повернення на циферблат не доведена**.
- Spotify Android/Wear OS Compose/Accessibility можуть змінити структуру вузлів або сховати потрібну кнопку.
- Натискання 88% висоти Карт/Watch7 — тестова поправка за спостереженням власника, без фізичного підтвердження.
- Bluetooth-гарнітура, вибір вбудованого мікрофона і безперервність SpeechRecognizer вимагають живого Watch7, Android обмежує фонове слухання.
- Bolt, Telegram, Macro, Finance, музика/карти та голосові відповіді на Pixel/Watch7 залишаються регресійними сценаріями, **не підтвердженими фізично**.

Не встановлювати версію як «stable» у GitHub: це тестовий кандидат з оригінальним підписом і збереженням пакета. Ніяких «усі проблеми усунуто» до підтвердження ручного тестування.
