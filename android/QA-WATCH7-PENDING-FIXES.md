# Дімон Watch7 — виправлення за ручним QA (ще без APK)

Стан: **внесено до вихідного коду окремої гілки, не включено до 0.1.40, APK не зібрано**.
Гілка: `fix/watch7-three-user-qa-issues-no-apk`. База: захист від асинхронних crash / некоректних ACK з PR #12; PR #12 ще не об'єднано з main.

## Помилка №1: гарнітура Bluetooth та мікрофон годинника
Спостереження користувача: коли на Watch7 підключені навушники, Дімон пізно слухає, сам припиняє запис або не чує фразу.

Код:
- `JarvisMicrophoneChoice.effectiveMode`: на Watch7 пріоритет вбудованого мікрофона поточного пристрою незалежно від phone/headset preference; Pixel зберігає свої налаштування.
- `JarvisHeadsetAudioRouter`: спроба маршрутизації на BUILTIN_SPEAKER/BUILTIN_MIC для запису; Bluetooth-аудіоподії не мають зупиняти Watch-сеанс при тимчасово недоступному маршруті; мінімізація повторних перемикань аудіо.
- `JarvisMicrophoneChoiceTest`: перевірки всіх збережених режимів і незалежності Pixel.

**Обмеження:** `SpeechRecognizer` є зовнішнім Android-сервісом і може не виконати побажання джерела аудіо. Фактичне захоплення саме вбудованим мікрофоном і збереження музики у Bluetooth-навушниках потрібно перевірити на фізичному Watch7. Жодних бездоказових гарантій «завжди» немає.

## Помилка №2: «Увімкни пісню ...» (Spotify)
Спостереження: надто короткий свайп; після ручного відкриття Search з'являється клавіатура, а текст пісні не вводиться.

Код:
- Довший свайп по екрану Watch7 (приблизно 76% висоти, 550 мс).
- До трьох спроб розгорнути навігацію через 2+ секунди, тільки коли Search відсутній та Spotify у передньому плані.
- Виявлення поля вводу Spotify при повноекранній Wear-клавіатурі; працювати лише з вузлом, що належить `com.spotify.music`, і лише дією `ACTION_SET_TEXT`.
- Новий крок `VERIFY_QUERY`: фактична назва пісні має з'явитися у полі перед Enter/вибором результату. До двох повторів у разі затримки; при невдачі — конкретне повідомлення, без випадкових натискань.
- `JarvisWatchUiRulesTest`: перевірки умов свайпу та точного збігу введеної назви.

**Ще не доведено:** реальна структура Spotify Accessibility на Watch7, натискання першої композиції, фактичне відтворення аудіо й плейлисти.

## Додаткові вимоги Spotify: головний екран і бібліотека плейлистів
Спостереження користувача: Spotify може відкриватися на плеєрі або попередній вкладці. До будь-яких автоматичних дій Дімон має перевірити домашній екран. Для іменованих плейлистів після свайпу вгору не відкривати глобальний Search — шукати назву безпосередньо в бібліотеці, прокручуючи список.

Код:
- `SpotifyStep.CHECK_HOME`: спочатку підтвердити головний екран по вибраній вкладці Home або характерній домашній секції. Якщо екран інший / невідомий, дати Spotify завантажитися (без раннього свайпу), закрити активну клавіатуру `DISMISS_IME` (тільки якщо вона відкрита), тоді `SWIPE_HOME` робить горизонтальний свайп вправо і перевіряє знову; максимум три спроби (без хаотичного натискання).
- `SpotifyStep.REVEAL_NAV`: довгий свайп угору (76% висоти, 550 мс) після домашнього екрана для всіх автоматичних типів: TRACK, PLAYLIST, RAP, UKRAINIAN.
- `SpotifyStep.FIND_LIBRARY_PLAYLIST`: для `PLAYLIST` шукає точну назву у видимих Accessibility-вузлах Spotify; **ніколи не викликає `OPEN_SEARCH`, `FOCUS_SEARCH`, `SET_QUERY`**.
- `SpotifyStep.SCROLL_LIBRARY_PLAYLISTS`: якщо назву не знайдено, робить свайп униз, чекає оновлення екрана, повторює пошук. Є ліміти: до 16 прокручувань, зупинка якщо двічі не змінився вміст, і загальний тайм-аут ~57 с.
- `JarvisWatchUiRulesTest`: перевірки визначення Home, бюджету свайпів вправо, точного збігу назви плейлиста, лімітів повторного прокручування.
- Кліки дозволені лише в додатку `com.spotify.music` та по видимих елементах Accessibility; координати Pixel не застосовуються.

**Важливе обмеження:** реальні назви та доступність Home/playlist Accessibility у Spotify на Watch7 поки не підтверджені. Якщо Spotify не відкриває потрібні вузли, застосунок безпечно повідомляє про неможливість продовжити, а не натискає навмання. Всі зміни — тільки вихідний код, не APK.

## Помилка №3: «Де я» (Google Maps)
Спостереження: відкривається початковий екран Карт із чотирма кнопками; Дімон не натискає верхню ліву кнопку із символом складеної карти.

Код:
- Новий крок `MapsStep.OPEN_MAP` перед пошуком позиції.
- Пошук підписаної кнопки карти, або — коли є назва «Нещодавні» і перевірена сітка чотирьох клікабельних плиток — натискання верхньої лівої плитки за її фактичними межами, а не за координатами Pixel.
- Повторна перевірка через 2 секунди, контроль очікування, помилка при недоступному UI; якщо відкрито саму карту, зайва кнопка не натискається.
- `JarvisWatchUiRulesTest`: без структури домашнього екрана випадкове натискання заборонено.

**Ще не доведено:** чи Wear Maps на пристрої відкриває доступ до всієї сітки через Accessibility. При нечитабельному дереві кнопку слід визначити зі справжнього UI dump, не «вгадувати» положення.

## Помилка №4: «Знайди дорогу до …» — спосіб пересування
Спостереження користувача: пошук адреси, вибір результату й відкриття маршруту на Watch7 проходять, але Дімон не натискає кнопку вибору способу пересування («Пішки», автобус тощо). Користувач указав місце натискання — центр у нижній частині екрана.

Код:
- `JarvisWatchMapsController`: після підтвердженого натискання `MapsStep.DIRECTIONS` Дімон спочатку намагається знайти кнопку «Пішки» по доступному тексту Accessibility.
- Якщо через 4,2 с відповідна кнопка не з'явилася, після додаткової перевірки екрану переходить до `MapsStep.TAP_MODE_BOTTOM`.
- `JarvisWatchScreenService`: одне натискання на годиннику (50% ширини, 88% висоти його власного дисплея). Не використовуються координати Pixel, не виконується натискання на головному екрані Карт, активній клавіатурі, полі пошуку або коли Карти не на передньому плані.
- `JarvisWatchUiRules` і `JarvisWatchUiRulesTest`: перевірка безпечних умов вибору кнопки, обмеження часу та підтвердження етапу маршруту.
- Після натискання Дімон повідомляє, що натиснув нижню кнопку, але **не стверджує без підтвердження**, що Google Карти справді обрали «Пішки» чи запустили навігацію.

**Потребує перевірки на фізичному Watch7:** чи саме на 88% висоти розміщена потрібна кнопка в поточній версії Google Карт; після підтвердження за потреби відкоригувати відносну координату.

## Помилка №5: Pixel — «Увімкни пісню ...» зупиняється на відкритому Spotify Search
Спостереження користувача: вкладка **«Пошук»** вже відкрита, у верхній частині екрана видно великий білий рядок **«Що ви хочете послухати?»**, але Дімон не натискає на рядок, показує «Не вдалося відкрити пошук Spotify».

Виправлення:
- `SpotifyTrackSearchRules.searchPrompt` відрізняє конкретний рядок вводу від заголовка «Пошук», вкладки внизу та музичних карток; підтримує український, російський і англійський текст.
- `ScreenControlAccessibilityService.spotifySearchTab()`: якщо рядок вводу вже видно, повертає `ALREADY` і не дублює натискання нижньої вкладки.
- `spotifyFocusSearch()`: спочатку перевіряє справжній редактор, намагається `ACTION_CLICK`; якщо Spotify Compose показує лише недоступний для `ACTION_CLICK` текст рядка, виконує жест **по центру підтвердженого рядка** у верхній зоні Spotify. Не торкається MiniPlayer або карток категорій.
- `SpotifyTrackSearchRulesTest`: відтворює пропорції скриншота Pixel 684×1536, перевіряє межі області й окремі підписи кнопок.

Потребує фізичного тесту Pixel: вкладка Search вже відкрита → натиснути рядок → клавіатура → назва пісні → Enter → вибір першого релевантного результату, а також запуск із Home, Library та плеєра. Автотести не доводять фактичне натискання у встановленому Spotify.

## Фізичний чек-лист (після майбутньої збірки)
- [ ] Bluetooth-навушники підключені: перший запуск мікрофона, 10 послідовних фраз; перевірити, що чутно годинник, а не мікрофон навушників.
- [ ] Відключити/підключити навушники під час сеансу; мікрофон не зупиняється без пояснення.
- [ ] «Увімкни пісню Пачка сигарет»: свайп → Search → текст → Enter → результат → реальний звук.
- [ ] Запуск Spotify із плеєра та з пошуку: якщо не Home — свайп вправо до Home (не більше 3 разів); українська, російська, англійська назви.
- [ ] Іменований плейлист у першому видимому списку після довгого свайпу вгору: натискання без глобального Search.
- [ ] Плейлист нижче у списку: свайп униз, повторне читання назви, без дублікатів і випадкових натискань.
- [ ] Відсутній плейлист: контрольована помилка після обмеженого прокручування, без нескінченного циклу.
- [ ] «Увімкни реп» та «Увімкни українське»: збереження попереднього алгоритму пошуку жанру після переходу на Home.
- [ ] «Де я»: початковий екран з чотирма плитками → верхня ліва карта → поточне місце.
- [ ] «Де я» коли карта вже відкрита: без зайвого натискання.
- [ ] «Знайди дорогу до …»: результат → маршрут → «Пішки» через Accessibility або одне натискання внизу по центру; перевірка, що натиснуто потрібну кнопку.
- [ ] Екран пошуку / клавіатура / головний екран Карт: ніяких випадкових натискань по нижньому центру.
- [ ] Друга команда маршруту поспіль: виконується без повторного натискання попереднього маршруту.
- [ ] Повернення до Дімона, повторний мікрофон, відсутність crash / повернення на циферблат.
- [ ] Pixel: «Увімкни пісню ...» коли вже відкрита вкладка «Пошук» — натискає великий білий рядок.
- [ ] Pixel: із Home Spotify переходить до вкладки Search, після чого натискає поле один раз.
- [ ] Pixel: ввід назви, Enter, перший результат, мініпрогравач і повторний запуск.

**APK поки НЕ збирати і НЕ публікувати.** Цей чек-лист стосується незiбраного коду, не релізу 0.1.40.
