# Джарвіс: крок 1 — контрольовані інструменти ШІ

База: `bc722e1de206f291161b7dad5d06ae04bd9203f0`.
Зберігаємо наявний Cloudflare Worker, `OPENAI_API_KEY`, `JARVIS_CLIENT_TOKEN`
і `OPENAI_MODEL`. Ключів у змінах немає. APK і підписування не змінюються.

## Що працює в цьому кроці

Невідомий локальному обробнику запит на телефоні передається у новий режим
`assist` через той самий `/chat`. Модель може запропонувати одну дію:
медіагучність (абсолютна/відносна), ліхтарик, play/pause/next/previous активного
програвача, створення або скасування таймера. Звичайна розмова повертає текст.
Головний екран і плаваючий сервіс використовують один виконавець і спільний
короткий контекст у RAM. На годиннику залишається попередній режим чату.

`tool-catalog.json` містить опис і схему кожного інструмента. Після редагування
серверного каталогу виконай `node tools/sync-tool-catalog.mjs`.
Для нової дії потрібні опис/схема, зареєстрована Android-функція і тести.
Планувальник переписувати не потрібно. Відсутня реалізація блокується.

## Захист і межі

- Worker використовує Responses function calling, `strict: true`,
  `parallel_tool_calls: false`, перевіряє власний whitelist і параметри.
- Android повторно перевіряє схему без приведення рядків до чисел/boolean.
- `confidence < 0.85` означає уточнення. Це допоміжна самооцінка моделі,
  а не гарантія правильного наміру і не дозвіл виконання.
- Новий ввід скасовує старий запит/підтвердження. Запит живе до 45 с,
  підтвердження — 30 с, використання одноразове. Автоматичних повторів немає.
- Скасування/заміна таймера та підвищення гучності до 85%+ потребують фрази
  **«Підтверджую дію»**. **«Скасуй дію»** скасовує пропозицію.
  Підтвердження прив'язане до незмінних параметрів та перевіреного стану телефона.
- Журнал містить час, інструмент і стан (100 останніх подій), без голосу,
  тексту розмови й ключів. **«Журнал дій ШІ»** показує останні 10 подій.
  Якщо початковий запис журналу неможливий, дія не виконується.
- Музика/ліхтарик повертають `submitted`: команда передана системі, фізичний
  результат не підтверджений. Немає неправдивої заяви про перевірене виконання.
- Пропозиції не приймаються в режимах фото, документів, пошуку, Python або
  звичайного чату. У режимі `assist` вкладення заборонені.
- Root, shell, довільний код, надсилання повідомлень, видалення, платежі та
  довільне керування екраном НЕ доступні моделі в цьому кроці.

Це початок міграції, не повна заміна старих обробників. Старі локальні команди,
макроси й Telegram зберігають попередню поведінку; цей журнал і політика
стосуються нового шляху ШІ. Історія локальних дій поки не входить у контекст ШІ.
Довготривалі уподобання, embeddings, навчання на виправленнях, багатокрокові
плани й переведення старих небезпечних дій на спільні підтвердження — наступні кроки.

## Перевірка

1. `node tools/sync-tool-catalog.mjs --check`
2. `cd server/jarvis-ai-worker && npm test` — відповіді API замінені тестовими,
   витрат OpenAI немає. Тести не перевіряють реальну якість розпізнавання намірів.
3. Workflow `Neural voice contract tests`: Java-контракти, регресії,
   `:app:compileDebugJavaWithJavac` без створення APK.

Для перевірки на телефоні після окремого оновлення Worker та встановлення
майбутнього APK:

| Запит/дія | Очікування |
|---|---|
| «Зменш медіагучність на десять відсоткових пунктів» | `volume_adjust`, перевірити реальну гучність |
| «Запусти зворотний відлік на три хвилини» | `timer_start`, 180 секунд |
| Другий таймер при активному першому | Запит підтвердження; до нього таймер не змінюється |
| «Підтверджую дію» двічі | Лише одне виконання |
| Підтвердження через 31 с або після іншої команди | Дію відхилено |
| Нова локальна команда під час очікування відповіді ШІ | Запізніла пропозиція не виконується |
| «А тепер вимкни» без контексту | Уточнення, без дії |
| «Видали файли» / «Надішли повідомлення…» через ШІ | Немає доступного інструмента, без дії |
| «Як вимкнути ліхтарик?» | Пояснення, без виклику дії |
| «Журнал дій ШІ» | Записи з фактичними станами |

Потрібно окремо перевірити ці фрази з живою моделлю: unit-тести гарантують
валідацію й керування станом, але не семантичну точність LLM.

Worker старої версії поверне зрозумілу помилку оновлення. Розгортання Worker
і випуск APK — окремі операції; цей крок їх не виконує.
